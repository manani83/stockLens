# 데이터 제공자 선택 기준

## 1. 평가 항목

- ETF 데이터 범위
- 배당 데이터 제공 여부
- 과거 분배금 이력 제공 여부
- 가격 데이터 제공 여부
- 환율 데이터 제공 여부
- 상업적 사용 가능 여부
- 재배포 가능 여부
- 호출 제한
- 월 비용
- 장애율
- 문서 품질
- TypeScript/REST 연동 편의성
- 캐싱 허용 여부

## 2. 점수표

후보별 점수는 1~5점으로 기록하고, 약관 확인이 끝나지 않은 항목은 비워 둔다.

| 평가 항목 | 중요도 | 후보 A | 후보 B | 후보 C | 비고 |
|---|---:|---:|---:|---:|---|
| ETF 기본정보 | 높음 |  |  |  |  |
| 배당 데이터 | 높음 |  |  |  |  |
| 과거 분배금 이력 | 높음 |  |  |  |  |
| 가격 데이터 | 중간 |  |  |  |  |
| 환율 데이터 | 중간 |  |  |  |  |
| 상업적 사용 | 높음 |  |  |  | 약관 링크 필요 |
| 재배포 가능 여부 | 높음 |  |  |  | 화면 표시와 원문 저장 구분 |
| 비용 | 높음 |  |  |  | 월 비용 기준 |
| 호출 제한 | 중간 |  |  |  | 캐시 전략 포함 |
| 문서 품질 | 중간 |  |  |  | 예제/오류 코드 확인 |
| TypeScript/REST 편의성 | 낮음 |  |  |  | 구현 비용 참고 |
| 캐싱 허용 여부 | 높음 |  |  |  | fallback 설계에 영향 |

## 3. 선택 원칙

- 무료라는 이유만으로 선택하지 않는다.
- 라이선스가 불명확하면 사용하지 않는다.
- 배당 데이터 정확성이 낮으면 핵심 계산에 사용하지 않는다.
- 장애 시 정적 데이터 fallback이 가능해야 한다.
- 가격 데이터와 배당 데이터는 서로 다른 소스를 사용할 수 있다.
- 특정 제공자를 선택하기 전에 약관 확인 날짜와 확인자를 남긴다.

## 4. 의사결정 기록 방식

- `docs/output/decision-log.md`에 데이터 제공자 선택 사유를 기록한다.
- 약관 확인 날짜를 기록한다.
- API 사용 범위와 제한을 기록한다.
- 캐싱, 저장, 화면 표시, 재배포 가능 여부를 별도 항목으로 남긴다.
- 실제 도입 전 `docs/harness/29_DATA_LICENSE_RISK_CHECKLIST.md`를 완료한다.
