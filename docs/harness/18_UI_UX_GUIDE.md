# UI/UX 정리 가이드

## 1. 디자인 원칙

- 정보형 도구 사이트로서 조용하고 읽기 쉬운 화면을 우선한다.
- 투자 판단을 유도하는 표현보다 참고용, 계산, 비교, 확인 중심의 표현을 사용한다.
- 입력, 결과, 안내 문구가 서로 겹치지 않도록 섹션 간 여백을 유지한다.
- 모바일에서는 카드와 단일 컬럼 흐름을 우선하고, 데스크톱에서는 표와 grid를 보조로 사용한다.

## 2. 공통 컴포넌트 목록

- `PageContainer`: 페이지 폭, 좌우 여백, 상하 여백을 관리한다.
- `PageHero`: 페이지 상단 eyebrow, h1, 설명 영역을 통일한다.
- `SectionCard`: 주요 섹션 카드 레이아웃을 제공한다.
- `InfoCard`: 핵심 수치와 짧은 설명을 표시한다.
- `ActionButton`: primary, secondary, ghost, danger 버튼 스타일을 통일한다.
- `EmptyState`: 데이터가 없을 때 안내와 선택 액션을 제공한다.
- `NoticeBox`: 정보, 주의, 위험 안내 문구를 일관되게 표시한다.

## 3. 페이지 레이아웃 규칙

- 페이지 본문은 `PageContainer` 또는 `page-shell` 기반 폭을 사용한다.
- 페이지당 h1은 하나만 둔다.
- 주요 섹션은 6단위 이상의 gap으로 분리한다.
- 기능 설명은 hero에 두고, 사용 방법을 길게 나열하지 않는다.

## 4. 버튼 사용 규칙

- 주요 실행은 `primary`를 사용한다.
- 페이지 이동이나 보조 액션은 `secondary`를 사용한다.
- 삭제는 `danger`를 사용한다.
- 단순 텍스트성 이동은 `ghost`를 사용할 수 있다.

## 5. 카드 사용 규칙

- 카드에는 `border`, `rounded-lg`, 충분한 padding을 사용한다.
- 카드 안에 또 다른 큰 카드를 중첩하지 않는다.
- 반복 항목은 카드 또는 테이블 중 화면 크기에 맞는 방식을 사용한다.

## 6. 테이블 사용 규칙

- 모바일에서는 카드형 목록을 우선한다.
- 데스크톱 테이블은 `overflow-x-auto`로 감싼다.
- 헤더는 명확한 한글 라벨을 사용한다.
- 숫자는 너무 작은 글씨로 표시하지 않는다.

## 7. 폼 사용 규칙

- 모든 입력에는 label을 둔다.
- input/select 높이는 터치하기 충분하게 유지한다.
- placeholder는 보조 설명으로만 사용한다.
- 오류 메시지는 사용자가 다음 행동을 알 수 있게 작성한다.

## 8. 투자 유의사항 표현 규칙

- “참고용”, “계산해볼 수 있습니다”, “비교해볼 수 있습니다”를 사용한다.
- “무조건”, “보장”, “확정 수익”, “반드시 매수” 표현은 사용하지 않는다.
- 데이터 출처와 공식 자료 확인 필요성을 명확히 표시한다.

## 9. 모바일 대응 체크리스트

- 주요 페이지가 단일 컬럼으로 자연스럽게 읽히는지 확인한다.
- 폼 입력과 버튼이 화면 폭 안에 들어오는지 확인한다.
- 테이블은 가로 스크롤이 가능해야 한다.
- 카드 텍스트가 버튼이나 다음 섹션과 겹치지 않아야 한다.
- 경고/고지 문구가 과하게 화면을 점유하지 않는지 확인한다.
