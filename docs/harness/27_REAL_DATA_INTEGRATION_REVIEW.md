# 실데이터 연동 후보 기술 검토

## 1. 검토 목적

- 정적 ETF 데이터에서 실데이터 기반 서비스로 전환하기 위한 사전 검토를 정리한다.
- 주가, 배당률, 분배금 이력, 운용보수, 환율, 캘린더 데이터를 안정적으로 관리하기 위한 후보를 비교한다.
- API 연동 전 라이선스, 비용, 호출 제한, 상업적 사용 가능 여부를 확인한다.

## 2. 필요한 데이터 종류

### 필수 데이터

- ETF 기본 정보
- ETF 현재가
- ETF 배당률 또는 분배율
- 운용보수
- 배당/분배금 지급 주기
- 배당락일
- 배당 지급일
- 환율

### 선택 데이터

- 과거 주가
- 과거 분배금 이력
- AUM
- 보유 종목
- 섹터 비중
- 수익률
- 변동성
- 뉴스

## 3. 데이터 소스 후보 유형

| 후보 유형 | 정확성 | 비용 | 자동화 가능성 | 라이선스 리스크 | 구현 난이도 | 최신성 | 장애 대응 |
|---|---|---:|---|---|---|---|---|
| ETF 운용사 공식 자료 | 높음 | 낮음 | 낮음 | 낮음 | 중간 | 중간 | 수동 fallback 필요 |
| 금융 데이터 API | 중간~높음 | 중간~높음 | 높음 | 중간 | 중간 | 높음 | 정적 데이터 fallback 필요 |
| 거래소 데이터 | 높음 | 중간~높음 | 중간 | 중간 | 높음 | 높음 | 제공 범위 확인 필요 |
| 브로커/증권사 제공 데이터 | 중간~높음 | 중간 | 중간 | 높음 | 중간~높음 | 높음 | 약관 의존 |

## 4. 단계별 추천 전략

1. 정적 데이터 + `dataAsOf` 표시, 수동 검증
2. CSV import 기반 수동 업데이트, 데이터 변경 이력 관리
3. 환율 API만 먼저 연동하고 ETF 데이터는 수동 관리 유지
4. 유료 또는 약관상 허용된 금융 API 검토 후 ETF 가격/배당 데이터 자동 업데이트
5. 관리자 기능 또는 백오피스 구축

## 5. API 연동 전 확인사항

- 상업적 사용 가능 여부
- 데이터 재배포 가능 여부
- 캐싱 가능 여부
- 호출 제한
- 비용
- 장애 시 fallback
- 데이터 기준 시간
- 배당 데이터 정확성
- 환율 기준
- 약관 변경 리스크

## 6. 결론

현재 MVP에서는 API 연동보다 CSV 기반 수동 업데이트가 현실적이다. 환율 데이터는 변동성이 크고 계산 결과에 직접 영향을 주므로 외부 연동 후보로 먼저 검토할 수 있다. ETF 배당 데이터는 라이선스와 정확성 이슈가 있으므로 운용사 공식 자료 검증과 수동 변경 이력 관리를 먼저 갖춘 뒤 자동화해야 한다.
