# 데이터 소스 아키텍처

## 1. 현재 데이터 구조

- 정적 ETF 데이터: `src/data/etfData.ts`
- 정적 캘린더 데이터: `src/data/calendarData.ts`
- localStorage 사용자 데이터: 관심종목, 알림 규칙, 포트폴리오, 백업/복원 대상 데이터

## 2. 데이터 소스 추상화 목적

- 정적 데이터에서 실서비스 데이터로 전환하기 위한 경계를 만든다.
- 외부 API, CSV, 수동 업데이트, 관리자 입력 방식으로 교체 가능성을 확보한다.
- 데이터 최신성 상태를 관리한다.
- 데이터 오류와 기준일을 추적할 수 있게 한다.

## 3. 데이터 소스 유형

- Static: 코드에 포함된 정적 데이터
- Manual: 사람이 공식 자료를 확인하고 수동 갱신
- CSV: 검증된 CSV 파일 업로드 기반 갱신
- External API: 외부 금융 데이터 API 연동
- Admin Managed: 관리자 화면에서 데이터 관리

## 4. 추천 전환 순서

1. 정적 데이터 + `dataAsOf` 표시
2. 수동 업데이트 정책
3. CSV import
4. 외부 API 연동
5. 관리자 데이터 관리

## 5. 주의사항

- 무료 API는 호출 제한과 데이터 지연이 있을 수 있다.
- 데이터 라이선스와 상업적 사용 가능 여부를 확인해야 한다.
- 배당 데이터는 기준일, 분배금 정책, 수정 공시를 함께 확인해야 한다.
- 환율 데이터는 기준 시각과 제공자를 명확히 해야 한다.
- 투자정보 제공 책임과 고지 문구를 검토해야 한다.
